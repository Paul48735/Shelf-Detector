# Shelf-Detector-v2

สำเนาโปรเจกต์สำหรับพัฒนาเวอร์ชันใหม่ แยกจาก Shelf-Detector เดิม

## โครงสร้าง

- ai/: Flask API, โมเดล YOLO, กฎ Planogram
- backend/api/: PHP API
- backend/config/: ค่าเชื่อม AI และ MySQL
- frontend/detect/: หน้าตรวจจับสินค้า
- frontend/dashboard/: หน้าภาพรวม
- frontend/planogram/: หน้าจัดแผนชั้นวาง
- frontend/shared/: CSS ที่ทุกหน้าใช้ร่วมกัน
- database/: SQL สำหรับฐานข้อมูล
- storage/: ภาพอัปโหลด ภาพผลลัพธ์ และภาพ Planogram

## ส่วนหน้า

หน้าเว็บใช้ Bootstrap 5.3.8 CSS ผ่าน jsDelivr CDN จึงต้องเชื่อมต่ออินเทอร์เน็ตเมื่อเปิดหน้าเว็บ
CSS ที่เขียนเองใช้กับส่วนอัปโหลดภาพ พื้นที่แสดงภาพ และตัวแก้ไข Planogram

## เริ่มใช้งาน

1. ใช้ Python 3.11 ขึ้นไป สร้าง virtual environment แล้วติดตั้ง dependencies ด้วย `pip install -r ai/requirements.txt`
2. เปิด Apache และ MySQL ใน XAMPP หากต้องการรองรับภาพใกล้ 10 MB ให้ตั้ง `upload_max_filesize=10M` และ `post_max_size=12M` ใน `php.ini` ของ Apache แล้ว restart Apache
3. นำเข้า database/shelf_detection.sql ในฐานข้อมูลใหม่ shelf_detection_v2 เท่านั้น (ไฟล์นี้สร้างฐานข้อมูลให้) ไม่ต้องนำเข้า add_product_placement.sql ซ้ำ
4. ตรวจชื่อผู้ใช้และรหัสผ่าน MySQL ใน backend/config/database.php
5. รัน `python ai/app.py` ซึ่งเปิด AI ที่ `http://127.0.0.1:8001`
6. เปิด `http://localhost/Shelf-v3/`

ถ้าเคยรัน `database/add_planogram_views.sql` กับฐานข้อมูลเดิม ให้รัน `database/remove_planogram_views.sql` หนึ่งครั้งเพื่อแปลง Planogram มุมย่อยเป็นแผนเดี่ยว (เติมชื่อมุมท้ายชื่อแผนเดิม) และเอาคอลัมน์หลายมุมออก แถว ภาพอ้างอิง พื้นที่ และประวัติการตรวจจะยังอยู่ครบ

การจัดแนวแบบ ECC ไม่ต้องเพิ่มตารางหรือคอลัมน์ฐานข้อมูล แผนเดิมยังใช้ได้ หากเคยเพิ่มคอลัมน์ `reference_corners` จากวิธีก่อนหน้า คอลัมน์นั้นจะคงอยู่แต่ระบบนี้ไม่ใช้งาน รีสตาร์ต Python AI service หลังอัปเดตโค้ด

### ใช้ Planogram

1. ในหน้า Planogram อัปโหลดภาพอ้างอิง วาดพื้นที่สินค้า และบันทึกแผน ควรใช้ภาพที่เห็นโครงสร้างชั้นวางชัดเจน และใกล้เคียงกับภาพที่จะตรวจ
2. ในหน้าตรวจจับ เลือก Planogram ของชั้นวางเดียวกัน อัปโหลดภาพใหม่ แล้วกดตรวจสอบ ระบบจะลองจัดแนวภาพอัตโนมัติ ไม่ต้องกดมุมภาพ

หากภาพถ่ายเฉียง ให้เปิด “ปรับ perspective ก่อนตรวจ (ทดลอง)” ในหน้าตรวจจับ ระบบจะใช้ OpenCV หาแนวขอบชั้นและเสนอ 4 มุมบนภาพต้นฉบับ พร้อมคะแนนรูปทรงและภาพที่ปรับแล้ว ตรวจว่าจุดทั้งสี่ล้อมชั้นวางตรงกับขอบเขตภาพอ้างอิงของ Planogram หรือไม่ ถ้าจุดผิดหรือไม่พบจุด ให้กด “กำหนด 4 มุมเอง” แล้วคลิกบนซ้าย → บนขวา → ล่างขวา → ล่างซ้าย จากนั้นดูภาพที่ปรับแล้วและกดตรวจสอบ ภาพที่ปรับแล้วจะเข้า Product Model และ Gap Model ก่อนจับคู่ผลกับ Planogram เดิม โดยหน้าเว็บแสดงภาพต้นฉบับ ภาพปรับมุม และภาพผลตรวจ คะแนนที่แสดงเป็นเพียงเกณฑ์รูปทรงของกรอบ ไม่ใช่ความน่าจะเป็นว่ามุมถูกต้อง จึงต้องยืนยันจุดที่ระบบเสนอทุกครั้ง

การปรับแบบนี้ต้องเห็นชั้นวางและเลือกขอบเขตเดียวกับภาพ Planogram การแปลงภาพสี่มุมไม่สามารถกู้ส่วนที่ถูกบังหรือแก้ความต่างเชิงลึกของวัตถุทั้งหมดได้ ภาพจากด้านข้างหรือด้านบนมากอาจทำให้ตำแหน่งสินค้าไม่ตรงกับพื้นที่ในแผน ควรตรวจภาพที่ปรับแล้วก่อนเชื่อผล ไม่ต้องเปลี่ยนตารางฐานข้อมูลหรือสร้าง Planogram ใหม่เพื่อเปิดฟังก์ชันนี้ เมื่อปิดสวิตช์ ระบบยังทำงานตามวิธี ECC เดิม

ระบบใช้ `cv2.findTransformECC` หา affine warp จากความเข้มภาพเพื่อจัดภาพใหม่เข้าพิกัดภาพอ้างอิง แล้วจึงส่งเข้า YOLO โดยไม่ใช้การกดมุมหรือ Feature Matching ขั้นแรกจะเทียบภาพเทาโดยรวม หากไม่สำเร็จและภาพทั้งสองเห็นชั้นไม้สีอ่อนเพียงพอ จะลองใช้ ECC เทียบส่วนโครงชั้นไม้แทน เพื่อให้ภาพอ้างอิงชั้นว่างใช้กับภาพชั้นที่มีสินค้าได้ดีขึ้น วิธีสำรองนี้อาศัยสีไม้ของชั้นวางตัวอย่าง จึงไม่ครอบคลุมชั้นสีหรือวัสดุอื่น หาก ECC ไม่ลู่เข้าหรือผลแปลงคลาดเคลื่อน ระบบจะตรวจเฉพาะวัตถุที่มองเห็นจากภาพเดิมและไม่ตัดสินถูก/ผิด shelf หรือระบุ Class ของ gap ตาม Planogram หากไม่เลือก Planogram จะตรวจภาพต้นฉบับโดยตรง ภาพมุมบนหรือมุมข้างมาก และภาพที่ส่วนชั้นวางถูกบัง อาจจัดแนวไม่ได้ ระบบไม่สามารถระบุสินค้าที่มองไม่เห็นหรือ YOLO ตรวจไม่พบกรอบได้

ภาพผลตรวจวาดกรอบสินค้าแต่ละชิ้นและ gap ตามกรอบต้นฉบับที่โมเดลตรวจพบ แม้เลือก Planogram อยู่ แผนใช้เทียบตำแหน่งและคลาสที่คาดหวังเพื่อกำหนดสีและป้ายกำกับ สินค้าหลายชิ้นในพื้นที่เดียวกันยังแสดงกรอบแยกแต่ละชิ้น ส่วน gap ที่ครอบหลายพื้นที่วาดกรอบโมเดลครั้งเดียวและระบุคลาสที่ขาดบนป้าย โดยข้อมูลผลลัพธ์ยังแยก gap ตามพื้นที่ของแผน

หน้า `frontend/detect/` ส่งภาพให้โมเดล YOLO ตรวจสินค้าและช่องว่าง ส่วน Planogram ใช้ระบุตำแหน่งสินค้าและสินค้าที่ควรอยู่ในแต่ละพื้นที่

### เพิ่มภาพและ Fine-tune โมเดลสินค้า

เปิด `frontend/training/` เลือกภาพสินค้าได้หลายภาพในครั้งเดียวเพื่ออัปโหลดเข้ารายการ จากนั้นกด “ติดป้ายกำกับ” และวาดกรอบสินค้าให้แต่ละภาพ ภาพเดี่ยวเปิดตัววาดกรอบได้ทันที ต้องมีภาพที่ติดป้ายกำกับแล้วอย่างน้อย 4 ภาพจึงเริ่ม Fine-tune ได้ หน้าเว็บจะแบ่งภาพเป็น train/validation และแสดงสถานะกับ metrics เมื่อฝึกเสร็จ ให้เลือกโมเดลในรายการ “เลือกโมเดลที่ใช้ตรวจจับ” แล้วกดเปิดใช้ ระบบจะแสดงโมเดลที่ฝึกเสร็จและไฟล์สำรองจาก `ai/models/archive/` ให้เลือก รวมทั้งเก็บสำเนาโมเดลเดิมทุกครั้งที่สลับ

ใช้คลาสเดิมถ้าเป็น SKU เดิม และใส่ภาพแพ็กเกจเก่าร่วมกับแพ็กเกจใหม่ รวมถึงตัวอย่างสินค้าอื่นที่ต้องการรักษาความแม่นยำไว้ ชุดฝึกที่เพิ่มจะถูกนำมารวมในการ Fine-tune รอบถัดไป

ค่าที่แยกจากโปรเจกต์เดิม: AI พอร์ต 8001 และ MySQL ฐานข้อมูล shelf_detection_v2

### คุณภาพการ Fine-tune

ระบบฝึกตัวเสริมจากโมเดลปัจจุบันด้วย AdamW, learning rate 0.0001 และ cosine decay พร้อม augmentation แบบเบา โดยไม่กลับภาพตัวหนังสือบนแพ็กเกจ ค่าเริ่มต้น 60 epochs และหยุดเมื่อคะแนนไม่ดีขึ้น 20 epochs ตัวเสริมเรียนรู้ทั้งเครือข่าย แต่ใช้ผลตรวจจับเฉพาะคลาสเป้าหมาย ส่วนคลาสอื่นใช้โมเดลต้นทางที่เก็บไว้ทั้งไฟล์

ภาพที่มีป้ายทุกคลาสใช้ร่วมฝึกเพื่อช่วยรักษาความแม่นยำเดิม ต้องติดป้ายสินค้าทุกชิ้นของคลาสที่โมเดลรู้จักในภาพ มิฉะนั้นสินค้าไม่มีป้ายจะถูกเรียนเป็นพื้นหลัง ควรมีอย่างน้อย 30–50 ภาพที่แตกต่างกันของคลาสเป้าหมาย รวมมุม แสง ระยะ แพ็กเกจ และภาพคลาสอื่น ส่วนขั้นต่ำ 4 ภาพใช้ทดลองระบบเท่านั้น

ระบบรวมภาพที่มีพิกเซลซ้ำเป็นภาพเดียวก่อนแบ่ง train/validation โดยใช้กรอบชุดล่าสุดของแต่ละคลาสและรวมป้ายต่างคลาสในภาพเดียวกัน รายการภาพต้นฉบับยังอยู่ครบ หากกรอบเดียวกันถูกติดป้ายคนละคลาสระบบจะแจ้งรหัสภาพให้แก้ก่อนฝึก จากนั้นพยายามให้คลาสที่มีภาพเพียงพออยู่ทั้งสองชุด ภาพใกล้เคียงจากวิดีโอหรือกล้องมุมเดิมยังอาจทำให้คะแนนสูงเกินจริง ควรทดสอบเพิ่มกับภาพคนละช่วงเวลา/สถานที่ที่ไม่ได้ใช้ฝึก

เมื่อฝึกเสร็จ ระบบวัดน้ำหนักตัวเสริมก่อนและหลังฝึกบน validation เดียวกัน แสดง mAP50–95 ของคลาสเป้าหมาย รวมถึงคำเตือนเรื่องข้อมูลไม่พอ คะแนนระหว่าง epoch เป็นคะแนนชั่วคราว คะแนนเมื่อเสร็จเป็นของไฟล์ best.pt ของตัวเสริม ไม่ใช่คะแนนของระบบรวมที่รักษาโมเดลต้นทาง ไม่มีการสลับโมเดลอัตโนมัติ และคะแนน validation ไม่รับรองผลกับภาพจริงที่แตกต่างจากชุดข้อมูล ผลแบ่งชุดเก็บใน `storage/training/jobs/<job-id>/dataset_summary.json`

### รักษาความสามารถของโมเดลต้นทาง

ในรายการเลือกโมเดล เลือกโมเดลที่ Fine-tune แล้วกด “ลบโมเดลที่ Fine-tune ที่เลือก” และยืนยันการลบ ระบบลบไฟล์โมเดลกับสำเนาที่เหมือนกันและเก็บประวัติงานไว้ ลบตัวที่กำลังใช้งานหรือต้นทางที่โมเดลอื่นอ้างอิงไม่ได้ และต้องรอให้งานฝึกเสร็จก่อน โมเดลต้นฉบับและโมเดลสำรองทั่วไปไม่มีปุ่มลบ

โมเดลที่ฝึกใหม่เป็นตัวเสริมเฉพาะคลาสเป้าหมาย ระบบเก็บน้ำหนักโมเดลต้นทางทั้งไฟล์เพื่อใช้ตรวจสินค้าเดิมด้วย จึงไม่พึ่งน้ำหนักของตัวเสริมในการจำคลาสอื่น คำอธิบายการฝึกทั้งเครือข่ายด้านบนหมายถึงการฝึกตัวเสริมเท่านั้น คะแนน validation เป็นคะแนนของตัวเสริม (target specialist) ไม่ใช่คะแนนระบบรวม

ไฟล์โมเดลที่ Fine-tune ใหม่มี metadata `shelf_preservation` ระบุ hash ของโมเดลต้นทางและคลาสเป้าหมาย ระบบสำรองต้นทางใน `ai/models/archive/bestProduct-<SHA256>.pt` และตรวจ hash ก่อนโหลด ขณะตรวจจับจะรันต้นทางเพื่อรักษาสินค้าเดิม พร้อมรันตัวเสริมเฉพาะคลาสเป้าหมาย ผลตัวเสริมที่ทับสินค้าคลาสอื่นจากต้นทางจะถูกตัดออก และเก็บผลคลาสเป้าหมายเดิมถ้าตัวเสริมไม่พบ การ Fine-tune รอบถัดไปเก็บต้นทางที่มีตัวเสริมก่อนหน้าไว้ด้วย การเลือกหรือย้อนกลับโมเดลจึงนำชุดต้นทางที่สัมพันธ์กันกลับมาด้วย

วิธีนี้เพิ่มเวลาและหน่วยความจำในการตรวจจับตามจำนวนตัวเสริม และให้ผลต้นทางของสินค้าคลาสอื่นมีลำดับความสำคัญสูงกว่า จึงอาจกันผลคลาสเป้าหมายใหม่ที่ต้นทางเคยจำผิดเป็นคลาสอื่น ต้องเก็บไฟล์สำรองที่ถูกอ้างอิงไว้ด้วยหากย้ายระบบ ไฟล์ `.pt` เมื่อนำไปรัน YOLO โดยตรงนอกระบบ Shelf จะได้เฉพาะผลตัวเสริม กลไกรักษาโมเดลเดิมอยู่ใน `ai/preservation.py`
