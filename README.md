# Shelf-Detector-v2

สำเนาโปรเจกต์สำหรับพัฒนาเวอร์ชันใหม่ แยกจาก Shelf-Detector เดิม

## โครงสร้าง

- ai/: Flask API, โมเดล YOLO, กฎ Planogram
- backend/api/: PHP API
- backend/config/: ค่าเชื่อม AI และ MySQL
- frontend/detect/: หน้าตรวจจับสินค้า
- frontend/dashboard/: หน้าภาพรวม
- frontend/planogram/: หน้าจัดแผนชั้นวาง
- frontend/shared/: CSS ที่ทุกหน้าใช้ร่วมกัน
- database/: SQL สำหรับฐานข้อมูล
- storage/: ภาพอัปโหลด ภาพผลลัพธ์ และภาพ Planogram

## ส่วนหน้า

หน้าเว็บใช้ Bootstrap 5.3.8 CSS ผ่าน jsDelivr CDN จึงต้องเชื่อมต่ออินเทอร์เน็ตเมื่อเปิดหน้าเว็บ
CSS ที่เขียนเองใช้กับส่วนอัปโหลดภาพ พื้นที่แสดงภาพ และตัวแก้ไข Planogram

## เริ่มใช้งาน

1. ใช้ Python 3.11 ขึ้นไป สร้าง virtual environment แล้วติดตั้ง dependencies ด้วย `pip install -r ai/requirements.txt`
2. เปิด Apache และ MySQL ใน XAMPP หากต้องการรองรับภาพใกล้ 10 MB ให้ตั้ง `upload_max_filesize=10M` และ `post_max_size=12M` ใน `php.ini` ของ Apache แล้ว restart Apache
3. นำเข้า database/shelf_detection.sql ในฐานข้อมูลใหม่ shelf_detection_v2 เท่านั้น (ไฟล์นี้สร้างฐานข้อมูลให้) ไม่ต้องนำเข้า add_product_placement.sql ซ้ำ
4. ตรวจชื่อผู้ใช้และรหัสผ่าน MySQL ใน backend/config/database.php
5. รัน `python ai/app.py` ซึ่งเปิด AI ที่ `http://127.0.0.1:8001`
6. เปิด `http://localhost/Shelf-v3/`

ถ้าเคยรัน `database/add_planogram_views.sql` กับฐานข้อมูลเดิม ให้รัน `database/remove_planogram_views.sql` หนึ่งครั้งเพื่อแปลง Planogram มุมย่อยเป็นแผนเดี่ยว (เติมชื่อมุมท้ายชื่อแผนเดิม) และเอาคอลัมน์หลายมุมออก แถว ภาพอ้างอิง พื้นที่ และประวัติการตรวจจะยังอยู่ครบ


### ใช้ Planogram

1. ในหน้า Planogram อัปโหลดภาพอ้างอิง วาดพื้นที่สินค้า และบันทึกแผน ควรใช้ภาพที่เห็นโครงสร้างชั้นวางชัดเจน และใกล้เคียงกับภาพที่จะตรวจ
2. ในหน้าตรวจจับ เลือก Planogram ของชั้นวางเดียวกัน อัปโหลดภาพใหม่ แล้วกดตรวจสอบ หากไม่กำหนดจุดอ้างอิง ระบบตรวจภาพต้นฉบับโดยตรง จึงควรถ่ายให้มุมมองและกรอบชั้นใกล้เคียงภาพอ้างอิง

### จัดแนวภาพเฉียงด้วยจุดอ้างอิง 4 คู่ (ไม่บังคับ)

1. หน้า Planogram กด “กำหนดจุดอ้างอิงโครงตู้ 4 จุด” เหนือภาพ แล้วคลิกบนภาพหลักตามลำดับ บนซ้าย → บนขวา → ล่างขวา → ล่างซ้าย แล้วบันทึกแผน จุดชุดนี้แยกจาก Polygon ของสินค้า กด “กลับไปวาดพื้นที่สินค้า” เพื่อกลับโหมดเดิม สามารถเปิดแผนเก่า เพิ่มจุด แล้วบันทึกเป็นแผนรายการใหม่ได้
2. หน้า Detect เลือกแผนที่บันทึกไว้และอัปโหลดภาพ คลิกจุดโครงตู้บนภาพใหญ่ในช่อง “ภาพวิเคราะห์” หรือภาพอัปโหลดด้านซ้ายในส่วนจัดแนวด้านล่าง จุดบนทั้งสองภาพใช้ข้อมูลชุดเดียวกัน ภาพ Planogram ด้านขวาใช้ดูหมายเลขอ้างอิง ลากจุดหรือใช้ปุ่มลูกศรเพื่อแก้ไขได้ หากแสดงผล Detect อยู่ กด “เลือก / แก้ 4 จุดบนภาพต้นฉบับ” หากแผนยังไม่มีจุด ระบบแสดงลิงก์เปิดแผนนั้นในโหมดกำหนดจุดให้โดยตรง
3. กด “แสดงภาพหลังจัดแนว” เพื่อตรวจแนวชั้นกับพื้นที่ Planogram ที่วาดทับก่อน กด “ตรวจสอบภาพหลังจัดแนว” เมื่อจุดตรงกัน หากต้องการตรวจภาพต้นฉบับ ให้ล้างจุดทั้งหมด
4. ไม่มีจุดบนภาพอัปโหลด = ไม่จัดแนว แม้ Planogram จะมีจุดอ้างอิงอยู่แล้ว เลือกไม่ครบ/กรอบไขว้/กลับลำดับ = แจ้งให้แก้ ไม่เงียบเปลี่ยนไปใช้ภาพต้นฉบับ แผนเก่าที่ไม่มีจุดยัง Detect ได้ตามเดิม

ระบบใช้ `cv2.getPerspectiveTransform` จากจุดภาพอัปโหลดไปยังพิกัดจริงในภาพอ้างอิง แล้ว `cv2.warpPerspective` ให้ได้ขนาดภาพ Planogram ก่อนส่งให้ Product และ Gap Model ทั้งสองตัว ภาพต้นฉบับยังเก็บไว้ กรอบผลตรวจจับอยู่ในพิกัดของภาพหลังจัดแนว ภาพหลังจัดแนวเก็บคู่กับผลตรวจจับและลบพร้อมประวัติรอบนั้น

จุดอ้างอิงเก็บใน `storage/planograms/<plan-id>.alignment.json` คู่กับภาพอ้างอิง ต้องสำรองไฟล์นี้พร้อมฐานข้อมูลและภาพ ไม่ต้องเพิ่มคอลัมน์ฐานข้อมูล ตัวอย่างภาพผ่าน `backend/api/detect.php?preview=1` ไปยัง `/alignment/preview` ของ Flask โดยไม่เรียกโมเดลและไม่สร้างประวัติการตรวจ ต้องรีสตาร์ต AI service หลังอัปเดตโค้ด และรีโหลดหน้าเว็บเพื่อใช้ไฟล์ JavaScript รุ่นใหม่

วิธีนี้เป็นการจัดแนวด้วยผู้ใช้ระบุจุด ไม่ได้ตรวจมุมอัตโนมัติ ต้องเลือกตำแหน่งจริงเดียวกันบนระนาบโครงตู้ที่เห็นในสองภาพ ไม่ใช้มุมสินค้า จุดที่ถูกบังหรืออยู่นอกภาพไม่ควรประมาณเอง การแปลงระนาบเดียวไม่ทำให้สินค้าที่มีความลึกต่างกันซ้อนทับกันเป๊ะ และไม่สามารถกู้คืนส่วนที่มองไม่เห็นได้ จึงต้องตรวจภาพตัวอย่างก่อนยืนยันตำแหน่งสินค้า




ภาพผลตรวจวาดกรอบสินค้าแต่ละชิ้นและ gap ตามกรอบต้นฉบับที่โมเดลตรวจพบ แม้เลือก Planogram อยู่ แผนใช้เทียบตำแหน่งและคลาสที่คาดหวังเพื่อกำหนดสีและป้ายกำกับ สินค้าหลายชิ้นในพื้นที่เดียวกันยังแสดงกรอบแยกแต่ละชิ้น ส่วน gap ที่ครอบหลายพื้นที่วาดกรอบโมเดลครั้งเดียวและระบุคลาสที่ขาดบนป้าย โดยข้อมูลผลลัพธ์ยังแยก gap ตามพื้นที่ของแผน

หน้า `frontend/detect/` ส่งภาพให้โมเดล YOLO ตรวจสินค้าและช่องว่าง ส่วน Planogram ใช้ระบุตำแหน่งสินค้าและสินค้าที่ควรอยู่ในแต่ละพื้นที่

### เพิ่มภาพและ Fine-tune โมเดลสินค้า

เปิด `frontend/training/` เลือกภาพสินค้าได้หลายภาพในครั้งเดียวเพื่ออัปโหลดเข้ารายการ จากนั้นกด “ติดป้ายกำกับ” และวาดกรอบสินค้าทุกชิ้นที่รู้จักในแต่ละภาพ ภาพเดี่ยวเปิดตัววาดกรอบได้ทันที หน้าเว็บฝึกทุกคลาสที่ติดป้ายพร้อมกัน โดยแต่ละคลาสต้องปรากฏในอย่างน้อย 4 ภาพที่แตกต่างกัน หน้าเว็บจะแบ่งภาพเป็น train/validation และแสดงสถานะกับ metrics เมื่อฝึกเสร็จ ให้เลือกโมเดลในรายการ “เลือกโมเดลที่ใช้ตรวจจับ” แล้วกดเปิดใช้ ระบบจะแสดงโมเดลที่ฝึกเสร็จและไฟล์สำรองจาก `ai/models/archive/` ให้เลือก รวมทั้งเก็บสำเนาโมเดลเดิมทุกครั้งที่สลับ

ใช้คลาสเดิมถ้าเป็น SKU เดิม และใส่ภาพแพ็กเกจเก่าร่วมกับแพ็กเกจใหม่ รวมถึงตัวอย่างสินค้าอื่นที่ต้องการรักษาความแม่นยำไว้ ชุดฝึกที่เพิ่มจะถูกนำมารวมในการ Fine-tune รอบถัดไป

ค่าที่แยกจากโปรเจกต์เดิม: AI พอร์ต 8001 และ MySQL ฐานข้อมูล shelf_detection_v2

### คุณภาพการ Fine-tune

ระบบฝึกตัวเสริมจากโมเดลปัจจุบันด้วย AdamW, learning rate 0.0001 และ cosine decay พร้อม augmentation แบบเบา โดยไม่กลับภาพตัวหนังสือบนแพ็กเกจ ค่าเริ่มต้น 60 epochs และหยุดเมื่อคะแนนไม่ดีขึ้น 20 epochs หน้าเว็บฝึกทุกคลาสที่ติดป้ายร่วมกันในรอบเดียว โดยต้องมีอย่างน้อย 4 ภาพต่อคลาส ตัวเสริมเรียนรู้ทั้งเครือข่าย แต่ใช้ผลตรวจจับเฉพาะคลาสที่ติดป้าย ส่วนคลาสอื่นใช้โมเดลต้นทางที่เก็บไว้ทั้งไฟล์

ต้องติดป้ายสินค้าทุกชิ้นของคลาสที่โมเดลรู้จักในภาพ มิฉะนั้นสินค้าไม่มีป้ายจะถูกเรียนเป็นพื้นหลัง ควรมีอย่างน้อย 30–50 ภาพที่แตกต่างกันต่อคลาสที่ต้องการปรับปรุง รวมมุม แสง ระยะ และแพ็กเกจ ส่วนขั้นต่ำ 4 ภาพต่อคลาสใช้ทดลองระบบเท่านั้น

ระบบรวมภาพที่มีพิกเซลซ้ำเป็นภาพเดียวก่อนแบ่ง train/validation โดยใช้กรอบชุดล่าสุดของแต่ละคลาสและรวมป้ายต่างคลาสในภาพเดียวกัน รายการภาพต้นฉบับยังอยู่ครบ หากกรอบเดียวกันถูกติดป้ายคนละคลาสระบบจะแจ้งรหัสภาพให้แก้ก่อนฝึก จากนั้นพยายามให้คลาสที่มีภาพเพียงพออยู่ทั้งสองชุด ภาพใกล้เคียงจากวิดีโอหรือกล้องมุมเดิมยังอาจทำให้คะแนนสูงเกินจริง ควรทดสอบเพิ่มกับภาพคนละช่วงเวลา/สถานที่ที่ไม่ได้ใช้ฝึก

เมื่อฝึกเสร็จ ระบบวัดน้ำหนักตัวเสริมก่อนและหลังฝึกบน validation เดียวกัน แสดง mAP50–95 เฉลี่ยของคลาสที่ร่วมฝึก รวมถึงคำเตือนเรื่องข้อมูลไม่พอ คะแนนระหว่าง epoch เป็นคะแนนชั่วคราว คะแนนเมื่อเสร็จเป็นของไฟล์ best.pt ของตัวเสริม ไม่ใช่คะแนนของระบบรวมที่รักษาโมเดลต้นทาง ไม่มีการสลับโมเดลอัตโนมัติ และคะแนน validation ไม่รับรองว่าทุกคลาสจะดีขึ้นหรือใช้ได้กับภาพจริงที่แตกต่างจากชุดข้อมูล ผลแบ่งชุดเก็บใน `storage/training/jobs/<job-id>/dataset_summary.json`

### รักษาความสามารถของโมเดลต้นทาง

ในรายการเลือกโมเดล เลือกโมเดลที่ Fine-tune แล้วกด “ลบโมเดลที่ Fine-tune ที่เลือก” และยืนยันการลบ ระบบลบไฟล์โมเดลกับสำเนาที่เหมือนกันและเก็บประวัติงานไว้ ลบตัวที่กำลังใช้งานหรือต้นทางที่โมเดลอื่นอ้างอิงไม่ได้ และต้องรอให้งานฝึกเสร็จก่อน โมเดลต้นฉบับและโมเดลสำรองทั่วไปไม่มีปุ่มลบ

โมเดลที่ฝึกใหม่เป็นตัวเสริมสำหรับทุกคลาสที่ติดป้ายในรอบนั้น ระบบเก็บน้ำหนักโมเดลต้นทางทั้งไฟล์เพื่อใช้ตรวจคลาสที่ไม่ได้ร่วมฝึกด้วย คำอธิบายการฝึกทั้งเครือข่ายด้านบนหมายถึงการฝึกตัวเสริมเท่านั้น คะแนน validation เป็นคะแนนของตัวเสริม ไม่ใช่คะแนนระบบรวม

ไฟล์โมเดลที่ Fine-tune ใหม่มี metadata `shelf_preservation` ระบุ hash ของโมเดลต้นทางและคลาสเป้าหมาย ระบบสำรองต้นทางใน `ai/models/archive/bestProduct-<SHA256>.pt` และตรวจ hash ก่อนโหลด ขณะตรวจจับจะรันต้นทางเพื่อรักษาสินค้าเดิม พร้อมรันตัวเสริมเฉพาะคลาสเป้าหมาย ผลตัวเสริมที่ทับสินค้าคลาสอื่นจากต้นทางจะถูกตัดออก และเก็บผลคลาสเป้าหมายเดิมถ้าตัวเสริมไม่พบ การ Fine-tune รอบถัดไปเก็บต้นทางที่มีตัวเสริมก่อนหน้าไว้ด้วย การเลือกหรือย้อนกลับโมเดลจึงนำชุดต้นทางที่สัมพันธ์กันกลับมาด้วย

วิธีนี้เพิ่มเวลาและหน่วยความจำในการตรวจจับตามจำนวนตัวเสริม และให้ผลต้นทางของสินค้าคลาสอื่นมีลำดับความสำคัญสูงกว่า จึงอาจกันผลคลาสเป้าหมายใหม่ที่ต้นทางเคยจำผิดเป็นคลาสอื่น ต้องเก็บไฟล์สำรองที่ถูกอ้างอิงไว้ด้วยหากย้ายระบบ ไฟล์ `.pt` เมื่อนำไปรัน YOLO โดยตรงนอกระบบ Shelf จะได้เฉพาะผลตัวเสริม กลไกรักษาโมเดลเดิมอยู่ใน `ai/preservation.py`
